# Autonomous sweep — 2026-11-07 12:00 (run 408)

## Increment
Run 407's "Next": give the loop an **action-class view of its own increments** —
`tools/loop_action_class.py`, a `selftest_all` job.

## What it does
Reads the last N `loop_runs/run-*.json`, classifies each increment into:

| class | what it is |
|---|---|
| `fold` | folded external literature into the graph |
| `probe` | built or extended a runnable rig / measurement |
| `build` | shipped a new tool / module / capability |
| `fix` | fixed a bug or a broken instrument |
| `consolidate` | consistency pass, red-team, audit, negative result, deepening without new input |

Structural signals first (a new `probe_*.py` → probe; a new harness file → build), then an
ordered keyword ruleset. Reports the distribution, the dominant fraction, the longest
same-class streak, and two flags: **monoculture** (one class ≥ 70% over ≥ 6 runs) and
**long_streak** (≥ 4 in a row).

**Heuristic and says so**, like `param_invariance_audit` — it reports a distribution and a flag,
the judgement stays manual. A monoculture flag isn't "the loop is broken": runs 403–405 were a
deliberate 3-run build/probe thread and that was correct. The tool's note names that exception.

## First output — runs 394–407
```
fold 5   probe 4   build 3   fix 2   consolidate 0
```
No monoculture flag (mix is varied). **But the zero is a real signal.** Runs 400 and 402 *had*
consolidation intent — a red-team pass, a consistency sweep — but each also shipped a rig or
fixed a bug in the same run and classified as `probe`/`fix`.

**The loop bundles consolidation with action.** It almost never does a standalone
look-without-changing pass. The bias is understandable — bundling feels efficient, and a
pure-look run produces no graph delta, which the loop's own metrics reward less. But run 407's
lesson is that the wrong *action class* is a failure aggregate metrics don't catch, and "always
couple looking with changing" is exactly that: the loop rarely gets a clean read on its own
state before acting on it.

## The fix (stated, not forced)
Not scheduling consolidation runs — that's its own miscalibration. Making `loop_action_class`'s
mix visible in the run summary, so bundle-or-not is a *choice* each run rather than a default.
