Every self-evolving-skill loop assumes a reliable evaluation metric exists; often none does. This work
makes the *metric* the evolving object — a composition of small typed drawback detectors under an
evolutionary lifecycle, selected for agreement with a **ten-item anchored reference set** and regularised
by consensus over unlabeled outputs. What evolves is the grading function; the fixed task sets it is
scored on never change; the output is an inspectable expression, not an opaque judge. It is valid:
+0.21 agreement with hidden ground truth on a locked set metric selection never reads (paired *p*=0.014).

**The safety result:** remove the anchor guards and the metric collapses into a *vacuous always-pass
detector* — and that collapsed metric **trains skills just as well**. So downstream task score cannot
validate a self-evolved evaluator: task score answers only *sufficiency*, not *validity*. Double Ratchet
(metric co-evolved with a lifecycle-managed skill loop) retains 88–110% of the lift ground truth or a
hand-written rubric buys, across MBPP+, Spider 2.0-Snow, report generation. When evolved skills gamed the
report rubric, an **independent judge** caught it and one added detector repaired it.

Bearing on the project: `holdout_tasks.py` is frozen and hand-written — the safe side of this result. The
finding is the counter-case (what a self-evolved gate collapses to) and its method (anchored reference set
+ consensus regularisation + independent judge) is the recipe if check-substance ever needs to adapt.

## The acceptor cluster (runs 203–205)
Three composable conditions on a self-improvement gate, all from mid-2026 small-model / open-runtime work:

1. **exogenous** — the acceptance signal must sit outside the agent's control, not authored or inspectable
   by it (SEAL, arXiv:2607.24300; Falsifiable Release Gates, arXiv:2607.13070)
2. **anytime-valid** — the commit decision must be a sequential test with a bounded false-commit
   probability, not a threshold on a noisy point estimate (PACE, arXiv:2606.08106)
3. **validity-checked** — the metric itself must be checked against an anchor the loop cannot edit, because
   task score only proves sufficiency (Who Grades the Grader, arXiv:2607.12790)

`holdout_tasks.py` satisfies (1) and (3) by being frozen and hand-written; (2) — a paired e-process in
`verify_loop_edit` — is the open, adoptable improvement.
