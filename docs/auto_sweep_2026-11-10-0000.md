## The finding
Current trace-based skill learning = **shallow trajectory retrieval + flat skill summarisation**,
which ignores temporal dependencies and outcome-conditioned topology.

**Trace2Tower:** abstract steps into canonical events → a unified graph (semantic compatibility +
transition dynamics + outcome evidence) → a **contrastive spectral decomposition** that isolates
stable, **success-aligned** modes while **suppressing failure-prone shortcuts**. The modes
populate a 3-level **skill tower**: action templates → procedural routines → task strategies,
refined by verifier-guided feedback. ALFWorld **87.31%** / 10.35 steps / 0.26 invalid actions;
WebShop 50.67% exact.

## Why it lands on the loop
`tools/skill_induction.py` mines the loop's increments into **flat `TASK_CLASSES`** — the exact
bottleneck this paper names. The refinement (recorded on the skill-induction node):

- organise induced skills by **abstraction level** — a reusable code idiom / a multi-step
  procedure (`fold → probe → fix`) / a strategy (`consolidation pass before a feature run`);
- **condition each on outcome** — did the increment land, did it survive holdout, did a later
  run withdraw it.

It's the **success-side companion** to `concept_diagevo_improve_from_a_hierarchical_error_cause_memory`:
DiagEvo keeps a hierarchy of what *fails* by cause; Trace2Tower a hierarchy of what *works* by
abstraction level. Two hierarchical memories, not one flat trace log. And "suppressing
failure-prone shortcuts" is a concrete mechanism against the exploration→exploitation decline —
a run reaching for the shortcut that worked before.
