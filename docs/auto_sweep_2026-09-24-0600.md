## What was built
`gather_context()` assembles what a proposer needs: `loop_metrics.compute()`, the experience-bank task-class
distribution, the skill library state (induced / retired), the loop-harness components + versions, and the open
question from the most recent sweep doc.

`heuristic_propose(context)` checks four dimensions — research quality (verified-citation fraction), mode
diversity (is one task class > 55% of runs?), harness economy (procedure prompt bloat), safety
(validation-pass rate). Each proposal names a component, a concrete change, a **falsifiable** prediction
(metric / direction / from / target), and a verification starting with `computable:` or `held-out + re-run:`.

`PROPOSER_PROMPT` is the exact input a model proposer receives; it returns the same JSON shape, and
`verify_loop_edit` + the held-out set are unchanged — heuristic or model, verification is identical.
