Agentic systems act through heterogeneous runtimes (coding hooks, SDK tools, browser automation,
managed-agent traces, API gateways, workflow engines), so one operational act — publishing code, changing
identity state, moving money, exporting data — is represented by many incompatible runtime records. The
governance question that makes hard: *what* action was approved, *what* evidence binds the approval to
execution, and can an independent verifier *reproduce* the action identity later?

CAVA is a runtime-semantics layer converting heterogeneous activity into **canonical runtime action
objects**. It sits **below Proof-Carrying Agent Actions (PCAA)** — PCAA is the deployer-owned
route-review-prove process; CAVA is the stable object that process governs. Formalises canonical action
identity, semantic pattern detection, approval binding, receipt integrity, runtime-portable projection,
attestation. Benchmark: 96 seeds × 384 variants — semantic equivalence/separation, **wrapper bypass**,
false-positive control, approval binding, receipt reproducibility, **attestation tamper detection**,
runtime portability, policy degradation, Azure deployment drills.

Bearing on the project: this is `pattern_evidence_carrying_termination` and `pattern_four_field_constraint`
generalised to the **action** level, and it is the concrete defence against `emergent_authorization_laundering`
— a laundered "I was allowed to X" fabricated in memory cannot produce a bound approval receipt an
independent verifier can reproduce.
