# Autonomous sweep — 2026-10-28 00:00 (run 364)

## Increment
Adversarial pass against **this project's own posture**, triggered by run 363. The finding
was significant enough that leaving it in a graph node would have under-propagated it.

## The pressure
The emergence-first fork is defended by a **task-shape** claim
(`docs/emergence_first_posture.md`, run 237): harness-only suffices for *elicitation-shaped*
work — named as "research direction-setting, graph engineering, adversarial reading, **most of
what this project's loop actually does**" — and only hits a ceiling on *capability-shaped* work.

AgenticQwen (run 363) presses on it: TAU-2 multi-turn tool use is procedural, in-domain and
tool-mediated — **elicitation-shaped by that definition** — yet a vanilla 8B scores **19.3**
where a trained 8B scores 51.7. If elicitation-shaped work were harness-solvable, the vanilla
floor should not sit that low.

## The part that was assumed, and is now measured
"Most of what this project's loop actually does" had never been checked. Classifying all
**295 recorded runs** with `skill_induction.classify`:

| task class | share |
|---|---|
| literature sweep | 35.3% |
| *(unclassified)* | 33.6% |
| build | 18.6% |
| doc refresh | 8.1% |
| consistency re-read | 3.7% |
| graph hygiene / design integration | 0.6% |

`literature sweep` + `build` ≈ **54%** — both multi-turn tool use carrying state across many
steps, structurally the TAU-2 shape. The posture's named elicitation examples map onto
`consistency re-read` + `design integration` ≈ **4%**, and *"research direction-setting" is not
a task class in the loop's own taxonomy at all.*

So the claim is not supported by the loop's own record. The distribution points the other way.

## The escape, stated fairly
TAU-2 is also long-horizon multi-turn, and the posture already concedes long-horizon planning
to the capability side. That escape is available — but it is **expensive**, because the loop's
own work has the same shape, so taking it moves this project's core activity onto the contested
side of its own line.

## Caveats — both real
- `classify()` is a keyword matcher and **33.6% fell to `other`**. The direction (sweep + build
  dominate) is robust; the exact percentages are not.
- Mapping each task class onto the elicitation/capability axis is **judgement, not measurement**.

## Secondary finding
That 33.6% `other` bucket is itself a result: `skill_induction`'s keyword vocabulary has drifted
from how increments are currently written. A measurement instrument slowly losing contact with
what it measures — the same family as the run-361 dead-signal bug, caught the same way (by
running it rather than trusting it).

## What would settle it
The comparison nobody has run: **vanilla small model + strong harness vs agentically-trained
small model, on this loop's own task mix** rather than on TAU-2. Every component exists — the
`call_model` seam, the probe rigs, the frozen held-out set. It needs a model budget.
