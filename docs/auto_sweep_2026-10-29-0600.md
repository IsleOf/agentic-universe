## What was wrong
`experience_bank.condense` was built around run 64, selftested against a synthetic corpus, and
**never called on real data**. The bank held 0 entries across 368 runs while janitor's
staleness view reported it healthy (run 367's vacuous pass).

## The wiring
`LoopSession._write_summary` now calls `condense()` on the run's own trace — **after**
`rec.close()`, so the file is flushed — followed by `prune(keep_n=200, grace=10)` on both
collections.

**Bounded by construction, not as a later addition.** Per
`concept_unmanaged_skill_libraries_silently_drift` (unbounded accumulation degrades retrieval)
and the run-360 memory-horizon rig (unbounded retrieval is worse than none past a crossover),
the prune ships *with* the wiring. `prune` is a no-op below `keep_n`, so the per-run cost is
negligible.

The bank directory is now **gitignored with a committed README** (operating rule 9) — it is
derived runtime state, regenerable from the traces. It was not ignored before, so wiring it
naively would have committed bank entries on every run.

## The bug I nearly shipped
The first selftest run after wiring wrote **4 workflow entries into the production bank** —
the *identical* test-writes-to-production mixing run 368 had fixed for the certificate log,
**one run later, in a new write path.**

It was caught only because run 368 had just made that failure mode salient enough to look for.
That is the general form of run 367's lesson: **a fix is scoped to existing call sites; a new
call site added afterwards starts outside that scope.**

The rule it yields: *any component writing to a shared production artifact must take a
destination override in its constructor, and its tests must be **required** to pass one — not
merely permitted to.* `LoopSession` gained `bank_base`, and two selftest checks now assert both
halves:

- `condense populates the bank from a real run trace` (tmp bank, non-empty)
- `selftests add nothing to the production bank` (before/after count unchanged)

## What the first real entry immediately exposed
Populating an empty store turned out to be the **first real test every consumer of that store
had ever had.** Two latent bugs surfaced within minutes, both invisible while the bank was
empty:

1. **`janitor.stale_bank_flags` passed the wrong type.** It handed `Registry().manifest()` —
   the whole dict — to `ExperienceBank.stale()`, which compares against the manifest **hash**.
   A populated bank would have reported **100% stale, forever**. Every other caller in the
   codebase already passed the hash. Fixed, with a regression guard.
2. **My own new selftest guard asserted the wrong invariant.** It checked *"the production bank
   is empty"* when the real property is *"the selftest added nothing to it"* — and went RED the
   moment run 369's own record landed a legitimate entry. Fixed to compare a before/after count.

Both are the same conflation this whole audit keeps surfacing: **a check that passes for the
wrong reason until its subject exists.**

## Honest scope — this does not close the loop
**Write-only today.** Nothing in the live loop *retrieves* from the bank. The bounded `top_k`
retrieval path (run 357) exists and is selftested but has **no live caller**. Populating the
bank makes Phase 2 real, gives the staleness view a subject, and is the prerequisite for
retrieval. It is not itself retrieval, and the README says so.
