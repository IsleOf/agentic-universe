## What changed
**+1 node** (474), **+4 edges** (2002):
`concept_owner_harm_is_a_distinct_threat_model_from_third_party_harm_and_credential_leak_through_normal_operation_is_its_central_case`

Current agent-safety framing almost entirely protects THIRD PARTIES from an
agent. Owner-harm inverts the question: how does a well-intentioned agent,
operating entirely within normal parameters, damage its own principal's
interests? Credential leak through normal operation is the paper's central
case — not misuse, not misalignment; the agent did the task correctly and the
harm was a side effect.

**Grounded the same day, live:** a diagnostic script in this session ran
`cat config.yaml` to check Aether's server-host setting — a legitimate,
requested read. The file's plaintext live OAuth access + refresh token printed
into the tool output and this session's own context. No policy violated, no
action refused correctly — the harm was in the OUTPUT of a permitted action,
which nothing built this session checks for.

Edges: `challenges` the run-471 boundary-check synthesis directly — this is a
genuine limit case, since there is no clean action-level boundary to put a check
at when the harmful thing is a property of the output, not the action;
`refines` frontier-scheming (owner-harm is usually the *compliant* agent, not
the deceptive one); `informs` the identity/reputation thread (a symmetric gap —
nothing protects the owner's secrets FROM the agent's legitimate operation);
`extends` `kill_reconcile`/`orphan_scan` (argues for a companion check class:
scan tool OUTPUT before retention, a different boundary shape than
process/action state).
