## The setup
Two monitor architectures over one trajectory, with the adversary given a knob:

| | sees | degrades with length | evadable by phrasing |
|---|---|---|---|
| **DIRECT** | the whole trajectory | **yes** (the less-is-more mechanism) | **no** — it sees everything, only noisily |
| **EaE** | extractor output only | no | **yes** — miss the extractor and the scorer never looks |

**Adaptation** = how much the saboteur has optimised its phrasing against the extractor.

## Result

```
L=2    adapt=0.0   direct=0.853   eae=0.853   eae_confident_miss=0.083
L=16   adapt=0.0   direct=0.462   eae=0.877   eae_confident_miss=0.072
L=16   adapt=0.3   direct=0.470   eae=0.583   eae_confident_miss=0.375
L=16   adapt=0.6   direct=0.417   eae=0.330   eae_confident_miss=0.652
```

**1. It reproduces the paper.** At L=16 against a non-adaptive adversary, EaE 0.877 vs direct
0.462 — and the gain *grows with length*, which is arXiv:2601.21112's own reported finding.

**2. It breaks where the paper doesn't look.** At adaptation 0.6 the **unfiltered** monitor
overtakes it (0.417 vs 0.330). Evading an extractor is a different and easier target than
evading a scorer, and filtering is what hands the adversary that target.

## The number that actually matters isn't the detection gap
It's the **confident-miss** column: **0.652 vs ~0**.

A monitor that is slightly worse is a tolerable monitor. A monitor that is **confidently wrong**
is a broken oversight signal — because the operator above it stops looking. EaE's misses are
false-cleans in which the pipeline reports safe *having believed it read the relevant material*.
The direct monitor's misses come wrapped in the uncertainty that noise implies.

Filtering doesn't just move the failure. It **removes the failure's warning label**.

## What this is not
The adversary's ability to trade scorer-evasion for extractor-evasion is an **assumption the
simulation encodes, not a result it produces** — `assess_extractor`'s verdict string says so
in the output rather than in a comment a caller won't read. If the two turn out to be the same
capability, the crossover disappears.

The paper doesn't measure it either. That is the point: this is an open question that now has
a **shape** and a falsifiable form — run both architectures against a red team explicitly
instructed to defeat the *extractor*, and see whether 16.8pp survives.

## What it changes here
The janitor and the cohort monitor are both built on filtering, so both inherit the exposure.
The `constrains` edges say: filter for **capacity**, but keep a second channel with an
**uncorrelated failure mode**. Two extractors that fail differently beat one good one, for the
same reason two monitors beat one.

Note this partly *withdraws* run 381's advice to `cohort_monitor` one run later. That's the
correct direction of travel: 381 gave it a derivation, 382 gives it the derivation's cost.
