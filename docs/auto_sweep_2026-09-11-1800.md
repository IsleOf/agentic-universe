Enterprise skill/tool/workflow packages are gated today by scans for structure, style, security — which do
not answer the deployment question: *does the package help a live agent complete tasks under the same
model, sandbox, and grading policy?* ACES runs **paired live trials** with and without a target skill,
normalises trajectories into ATIF (Agent Trajectory Interchange Format), grades six runtime metrics, and
reports **Skill Lift**.

- **Spearman ρ = 0.14** between scan-only gates and LLM-judge evaluation on 145 real skills — they measure
  **complementary, near-orthogonal facets**.
- 947 scored paired cases, 58/64 production skills, four harnesses: mean composite Skill Lift **0.2134**
  (95% paired-case CI [0.1967, 0.2301]); mean outcome-only lift 0.1799; composite lift positive in
  **72.8%** of paired cases.
- Largest process-metric gains: skill execution, behaviour check, skill efficiency — discovery / routing /
  workflow-following / tool-use signals that document scans cannot observe.
- Open-source as NVIDIA SkillEvaluator.

Bearing on the project: (1) the with/without paired-trial design *is* `verify_loop_edit`'s
`baseline_scores` vs `candidate_scores` and SEAL/PACE's paired comparison — an independent
enterprise-scale instance; (2) **ρ = 0.14 is the empirical proof that `artifact_phase5_exec_guard`
(scan-only) and `artifact_phase3_holdout_set` (behaviour) are not redundant** — each catches what the
other cannot; (3) Phase 4 skill induction checks structure — ACES says structure is near-orthogonal to
value, so an induced skill needs a positive-Skill-Lift paired trial before promotion.
