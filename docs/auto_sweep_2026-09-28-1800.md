## The question
Does short-agent + four-field-constraint handoffs + deterministic folded state actually *compose* into
something that can do long work — or does the decomposition just move the compounding failure from steps to
handoffs?

## The rig
A long task = N dependent sub-steps, three configs swept over N:
- **A** one long agent (growing accumulation penalty)
- **B** decomposed, prose handoffs (shed prob 0.35 — 2608.24569)
- **C** decomposed, four-field handoffs + folded state (shed prob 0.01)

## Dry-run result (p_step 0.985, 600 trials/point)
| length | A | B | C |
| --- | --- | --- | --- |
| 12 | 0.58 | 0.57 | **0.86** |
| 24 | 0.12 | 0.20 | **0.64** |
| 100 | 0.00 | 0.00 | **0.19** |

**Verdict: COMPOSES BUT BOUNDED.** C dominates A and B at every length and doubles the usable horizon (task
length with success ≥ 0.5: A = 12, C = 24). **Not falsified** — the decomposition genuinely helps and
four-field beats prose. But the base per-step failure rate still sets a ceiling (0.985^100 ≈ 0.22). The design
*extends* how long a task can be; it does not make long work reliable. **You need short *tasks*, not just short
*agents*** — the orchestration layer's decomposition is doing at least as much work as the harness layer.
