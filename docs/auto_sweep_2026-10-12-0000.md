## What it does
Every probe adapter (`model_policy`, `model_relay`, `model_reader`, …) and
`loop_conductor.run_worker` want `call_model(prompt: str) -> str`. `call_model.py` is that
seam with a pluggable backend:

| `AU_MODEL_BACKEND` | behaviour |
|---|---|
| `fake` (default) | deterministic, offline — echoes a digest + a canned fail-safe shape (`"no"` for a yes/no forward question, `"[]"` for the proposer, an unparseable string for the idle-agent). For tests and dry runs. |
| `cli` | shells out to the local CLI-agent pool (`C:\Agents\skills\CLI-AGENT-CONTROL\agentctl.sh run <AU_MODEL_AGENT>`) — **no new API key needed** |
| a registered callable | `from call_model import register, set_backend; register("openai", fn); set_backend("openai")` |

`judge(a, b, criterion) -> "A" | "B"` (for `probe_rho_holdout`) is built on `call_model`;
`scripted([...])` is a test context manager. Every backend error returns a `"[…"` string,
so downstream fail-safe parsers treat it as garbage rather than crashing.

The `fake` and `callable` paths are pure stdlib and touch **no network and no
subprocess** — the selftest only exercises those. The `cli` path uses `subprocess` to
call an already-installed, already-authed local tool and is strictly opt-in.
