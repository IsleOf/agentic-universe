## The argument
MAS research works but is stuck in **trial-and-error** because of **attribution ambiguity**:

1. **No structured taxonomy of factors** → researchers make *unguided* adjustments.
2. **No unified metric** → a performance gain can't be attributed to *genuine collaboration* vs
   simply *more budget* (more agents = more compute = more samples).

**Proposal:**
- A **collaboration gain metric Γ** — isolate intrinsic gain from increased budget.
- A **factor attribution paradigm** using Γ to find the collaboration-driving factors.
- A **MAS factor library** — design space split into **control-level presets** and
  **information-level dynamics**.

## Two gaps it names in this project

**The Γ gap.** `probe_emergent_synergy`'s Rosas Ψ + differentiation *is* the project's
Γ-in-spirit (genuine collective vs aggregate). But `probe_orchestration_value`'s *"when does
multi-agent help"* verdict is **suggestive without a budget-matched baseline** — a single agent
given k× the samples. Adding that arm makes the collaboration gain a Γ, not a comparison of
selection rules. Cheap to add.

**The taxonomy map.** control-level presets vs information-level dynamics maps onto the swarm
substrate: `task_ledger` stage + `relay` handoff protocol are **control-level presets**; the
`pheromone` board signal + `reputation` are **information-level dynamics**. The design doc should
say which level each module is, so a change is attributed to the right one.
