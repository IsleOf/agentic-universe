An extensible Python library (Apache 2.0, HF-native) organised around **four model control surfaces**:

1. **input** — modification of the prompt
2. **structural** — modification of weights or architecture
3. **state** — modification of activations and attentions
4. **output** — modification of decoding / generation

Steering methods exert control through a common **steering pipeline** that also composes multiple methods;
use-case classes define tasks, a benchmark class compares performance.

The taxonomy is a useful orientation device — it partitions the project's positions cleanly: **input** =
`context/loop_policy` + ACE context evolution; **structural** = the weight-training fork the project
*declines* (WHALE / JIT-Agent); **state** = `pattern_activation_probe_monitoring` + the context-privesc
concern; **output** = the diversity toolkit (verbalized sampling, entropy-max). The project deliberately
works three of four surfaces and leaves the fourth on the table — exactly the WHALE/JIT-Agent tension, now
with a clean name.
