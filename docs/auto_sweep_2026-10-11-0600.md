# Autonomous sweep — 2026-10-11 06:00 (run 326)

## Increment
Hardened **`loop_conductor.pick_increment`** (v2.3) — the IDLE-STATE classifier now
consults the janitor's drift report over the **real run corpus**, not just a hand-fed
`recent_kinds` list.

## What changed
- `_corpus_drift(runs_dir=None)` — reads `janitor.load_runs()` + `janitor.drift_report()`
  and returns `(idle_streak, novelty_ratio)`; returns `(None, None)` and the caller falls
  back to `recent_kinds` if the corpus can't be read.
- `pick_increment(..., use_corpus=True, runs_dir=None)` — an idle streak `>= PLATEAU_WINDOW`
  (3) **or** a novelty ratio `< 0.34` (`loop_metrics` threshold) forces the IDLE-STATE
  `must_be_abc` clause **even when `recent_kinds` looks active**. The `reason` names which
  signal fired.
- `Conductor.conduct(..., use_corpus=True, runs_dir=None)` threads the flags through, with
  a `TypeError` fallback for a caller-supplied `choose_increment` that lacks the kwargs.

## Why
Run 303 built the classifier but it was hand-fed — the caller had to pass `recent_kinds`
and `frontier_swept` correctly. The failure mode that matters (the loop producing
gate-passing folds that only re-cite its own corpus) is exactly what `janitor`'s
`drift_report` measures. Now the conductor can't miss it: the classifier reads the real
history and refuses another marginal fold when novelty has collapsed.
