## What it does
`check(proposal, baseline_scores, candidate_scores, forecast, *, repaired=False)`:
1. runs `improvement_loop.verify_loop_edit` — frozen held-out set + category-masking +
   tamper + legibility;
2. carries the PACE anytime-valid **e-value**;
3. adds a **process-adjusted** flag — a pass that only holds after a `deterministic_repair`
   is downgraded `accept → accept_conditional` (the AgentLens shape, run 298: score the
   process, not just the outcome);
4. scores the proposer's **forecast** — it stated `P(edit helps)`; Brier it against the
   held-out outcome (the `epistemic_constitution` shape, runs 293/296);
5. emits a signed certificate `{proposal_hash, gate, e_value, forecast:{brier},
   certificate_hash}` to an append-only log (`runtime/observations/certificates/`,
   gitignored).

`verify_certificate(cert, proposal)` recomputes the proposal hash, the certificate hash,
and the Brier — the "an independent verifier can replay it later" property from the
six-condition acceptor spec (runs 203–214).

**Exogenous:** nothing in the module lets a proposer edit the held-out set, α, or a past
certificate. That is the whole point (`concept_reliable_self_improvement_needs_an_exogenous_acceptance_signal`).
