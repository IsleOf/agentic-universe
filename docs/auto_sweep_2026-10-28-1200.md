# Autonomous sweep — 2026-10-28 12:00 (run 366)

## Increment
Two instrument-decay bugs in two runs is a base rate, not a coincidence — so this run audited
**every** signal `loop_metrics` reports against live data instead of waiting to trip over the
third. It found it immediately, and it is the worst of the three.

## The finding
`compute()` reads **two corpora**: a frozen 56-run replay of the early evolution_log
(`runtime/traces/loop-history.jsonl`) and the live per-run summaries. Most headline metrics
were computed over the replay alone.

```
runs        56          <- the frozen replay
runs_live   297         <- what the loop has actually done
history_dominance  5.3
```

**For roughly 240 runs, the loop's reported health has been describing runs 1–56.**

The tell was in plain sight the whole time: `verified-frac 0.774` appeared *identically* in
every status line this session. A plausible constant reads as a stable system.

## The divergence, once measured

| metric | frozen | live |
|---|---|---|
| `verified_citation_fraction` | 0.774 | **0.92** |
| `graph_write_rate` | 0.429 | 0.333 |

The loop's real verification discipline is **better** than the number driving
`propose_loop_edit`.

## The near-miss worth keeping
`propose_loop_edit` gates `verified_citation_fraction` at **0.6**. Frozen (0.774) and live
(0.92) both sit above it, so **no spurious proposal fired — by luck, not design.** The
dangerous direction is the other one: had live verification fallen below 0.6 while the frozen
value held at 0.774, the loop would have been **blind to a real regression in its own citation
discipline**. A stale instrument is not merely imprecise; it is uninformative in exactly the
situation it exists to detect.

## The fix — a contract, not fresher data
- **Live counterparts:** `runs_live`, `verified_citation_fraction_live`, `graph_write_rate_live`.
- **`corpus_provenance`** — a map labelling *every* key `history` / `live` / `blended` / `meta`.
- **`history_dominance`** — published, not hidden.
- **Selftest guards:** every metric must declare its corpus (a new metric cannot be added
  without saying what it measures), and live metrics must *move with the live corpus while
  history metrics stay put*.

The history replay is not deleted — it is a real corpus with real Phase-1 uses. The bug was
never that it existed; it was that nothing said which number came from where.

would have fixed one instance; a declared contract makes the class visible.
