## What was built

`tools/orchestration_ledger.py` — `OrchestrationLedger(path=DEFAULT)` over a
committed `runtime/observations/orchestration_ledger.json`:

- `.claim(run_no, agent=None)` → marks a run `dispatched` with a timestamp;
  idempotent refresh while still dispatched; refuses to re-claim a run already
  `done`.
- `.complete(run_no, sha, node_delta=None, edge_delta=None)` → marks it `done`.
- `.status()` → highest `done` run, any `dispatched`-but-not-`done` runs (stale
  in-flight — a session died mid-run), and the next run number. Deterministic.
- `.record_gate(run_no, verdict)` → stores a `sweep_audit` verdict string on the
  run entry. Advisory; never blocks a claim or a complete.

Atomic write (`tmp` + `os.replace`) + a sibling `.audit` append log, same
discipline as `tools/task_ledger.py`. `PORTABILITY_CLASS = fixed-schema`. Pure
stdlib. Selftest sweeps the block size `n` over `range(2, 16)`
(claim/complete each, assert `status()` stays consistent) plus the
stale-in-flight, re-claim-refusal, idempotency and reload-from-disk cases:
90/90 checks GREEN. Added to `tools/selftest_all.py` JOBS.
Seeded the committed ledger with real state: run 463 `done` (sha `ef9e8a7`),
run 464 `dispatched`.
