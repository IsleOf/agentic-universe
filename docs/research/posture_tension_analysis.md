# The owner's research vs the project's posture (run 275)

A consistency pass on the *shape* of the owner's 54-direction research input, not the
individual folds. The 9-group fold (runs 259–268) added ~35 nodes. This asks: does that
body of research sit with the project's emergence-first posture, or pull against it?

## The project's posture, restated

`approach_emergence_first` + `principle_affordance_over_constraint`: give agents
capability, context and room; observe what they do; build structure around the behaviour
that proves useful. A constraint added *before* the behaviour is understood forecloses
the observation. `emergence_first_posture.md` also names a **second bet** (run 237): no
weight training — harness-only improvement, which holds for elicitation-shaped tasks and
hits a ceiling on capability-shaped ones (WHALE / JIT-Agent challenge it).

## Where the owner's research agrees

Most of it. The directions that *are* emergence-first:

- **Ecological / intrinsic (part 1: 1–3, 6):** intrinsic discovery, quality-diversity,
  ecological orchestration, productive scarcity — all "give room, observe what emerges".
  SwarmWorld (`concept_swarmworld_...`) is a direct restatement: homogeneous agents
  differentiate under constraints alone.
- **Quality-diversity + homeostasis (part 1: 2, 8; part 4: 40):** these *implement* the
  diversity keystone the project already holds — they are mechanism, not a new stance.
- **Structural coordination (part 4: 32, 33, 38):** the orchestratorless flock, fractal
  decomposition and cellular agents are all "global structure emerges from bounded local
  contributions" — the run-273 flock-arm probe confirmed stigmergic accretion is a real
  integration mode.
- **Curriculum refinements (part 3: 23–25, 31):** SPADE / LURE / DiagEvo instantiate
  `concept_environment_evolution_curriculum` — the environment co-evolves rather than
  being specified.

## Where it pulls against

A cluster of directions is **control-first**, not emergence-first. Named honestly:

| direction | the pull | how the graph holds it |
|---|---|---|
| #35 constraint-first orchestration | "specify the constraints that define a flourishing system, agents invent inside the feasible region" | This is actually *compatible* — it constrains the boundary, not the behaviour. Folded as PARTIAL against `principle_terminal_gate_only`. |
| #36 polycentric governance / #48 red-team institutions | permanent governance/adversary structures, defined up front | Genuine tension: these are structure *before* the behaviour. Held via `pattern_ostrom_swarm_governance` (which the project already accepts as the exception — governance is the one thing you design in advance because its absence is not observable until it is too late). |
| #39 deterministic spine / generative edge | consequential execution is deterministic and policy-bound | **Not a tension — this is the frame that makes emergence-first safe** (`edge_spine_edge_grounds_emergence_first`, run 262): the interior is free *because* the spine is not. |
| #42–53 epistemic-market cluster | organise agents around claims/forecasts/pre-registration | Structure-heavy, but the structure is *epistemic hygiene*, not behavioural specification. It constrains how a claim earns influence, not what an agent may think. |
| #49 truthful friction | deliberate latency at irreversible boundaries | Compatible — risk-proportionate, and `concept_irreversibility_budget` already does this. |

## The one real tension

**`concept_productive_scarcity_is_a_research_instrument_not_a_desirable_default`**
(run 266) is the only fold that carries a `challenges` edge on `approach_emergence_first`
— and correctly so. Scarcity is emergence-first in method (give a pressure, observe), but
the *observed* emergent behaviour includes loans, vote trading and strategic exclusion.
The posture says "build structure around the behaviour that proves useful"; scarcity
shows some emergent behaviour is useful to the agents and harmful to the system. This is
the same lesson as `emergent_deception_and_collusion` — emergence is not self-certifying.

The owner's own direction 11 answers it: the **emergence safety-case template**
(`artifact_emergence_safety_case_template`, run 268) — point 4 (failure analogues) and
point 6 (transfer test) are exactly the checks that catch "emergent but harmful".

## Verdict

The owner's research **does not** pull the project off emergence-first. ~40 of the 54
directions are emergence-first in method; the control-heavy cluster is either (a) the
already-accepted governance exception, (b) the spine/edge frame that *enables* a free
interior, or (c) epistemic hygiene that constrains influence-earning, not thought. The
single genuine tension — productive scarcity — is held by a `challenges` edge and
answered by the owner's own safety-case template.

What the fold *does* shift: it adds a heavy **epistemic-market / evaluation** emphasis
the graph was thin on. That is a gap-fill, not a stance change — the project always held
`principle_terminal_gate_only` and the acceptor/certificate cluster; the owner's research
gives the *proposer* side the same rigor the *acceptor* side had.
