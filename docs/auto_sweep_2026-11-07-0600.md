## The diagnostic
Aggregate accuracy on tool-calling benchmarks averages over many multi-turn situations and
hides whether progress is balanced. Decompose failure into two **orthogonal** modes:

1. **Action-class miscalibration** — choosing the wrong *kind* of action over
   `{TOOL_CALL, ASK, REFUSE, CONFIRM}`.
2. **Action-execution failure** — right kind, wrong details.

A self-revealing bound: **`Acc ≤ GAR`** (Gold Action Recall). `Acc > GAR` is a bound violation
that **exposes the state grader masking miscalibration**; `GAR >> Acc` localises execution
failure inside `TOOL_CALL`.

## Findings
- Action-class miscalibration is **substantial and invisible to the state grader**.
- It **inflates the standing of heavily tool-trained families** — they `TOOL_CALL` when they
  should `ASK/REFUSE/CONFIRM`.
- Calibration is reshapable by **context-only** perturbations, but heterogeneously: the same
  perturbation moves accuracy **+11.5 pp for one family, −21.0 pp for another** on the same
  scenario.

## Why it lands here
- *"Aggregate accuracy masks the failure mode"* **is** the vacuous-pass shape — a metric that
  looks fine because it never checks the thing that broke.
- Same *decompose, don't average* methodology as the cascade-radius orchestration diagnostic.
- **The loop's own increment choice is an action-class problem.** The IDLE-STATE RULE gives it a
  small action space (fold literature / dry-run a probe / consistency pass) plus build /

  whether the **class** was appropriate for the frontier state. `holdout_tasks` produces an
  aggregate — it wouldn't catch the loop systematically folding when it should be consolidating.
