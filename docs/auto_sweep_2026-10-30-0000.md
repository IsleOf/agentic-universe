## What was added
`LoopSession._file_footprint_vs_head()` — same mechanism as `_autodelta_vs_head` (run 361),
diffing the working tree against HEAD. On every run summary:

| field | why |
|---|---|
| `added` / `modified` / `deleted` | counts |
| `deleted_paths` | **in full, never truncated** |
| `unexpected_paths`, `n_unexpected` | paths outside the expected prefixes |

**Deletions get their own field and no truncation** because this loop is append-mostly — a
deleted file is the strongest disturbance signal it can produce, and the one thing that should
never happen unnoticed.

**Unexpected paths are reported, not refused.** Whether a path is out of place is a judgement
for the reader, not one a prefix list should make silently — that's the run-365 lesson about
classifiers with confident fallbacks.
