## Why
Run 462's "Next" named exactly this: a probe that runs a scenario N times and
reports all-of-N vs mean pass, sweeping N, because the loop's own eval reports
pass/fail once. Its open question — does `sweep_audit` (run 453) assume single-run
sufficiency? — is answered here by making that assumption checkable.

## What was found
- **The rig.** `consistency_gap(scenario, n, blocks)` runs any stochastic
  `scenario() -> bool` n times per block and reports `mean_pass` (all individual
  runs), `all_of_n` (blocks where every run passed), `gap = mean_pass - all_of_n`.
  `sweep_n` sweeps block size k over `range(2, 16)`.
- **The sweep is the diagnostic.** Gap is exactly 0 at every k for a deterministic
  scenario; for flaky p=0.8 the gap runs 0.16 (k=2) → 0.47 (k=5) → 0.76 (k=15)
  while `mean_pass` holds at ~0.8. A near-deterministic p=0.97 scenario still opens
  a >0.15 gap by k=15 — "looks fine at k=2" is not single-run-sufficiency.
- **`flip_risk(p, thresh)`** — the loop-facing number: the block size at which
  independent all-of-k success `p**k` drops below a decision threshold that mean
  pass clears. For a 0.9 bar, p=0.95 flips at k=3; p=0.995 at k≈22. So a single-run
  `audit ok` on a headline with p just above the bar is itself a
  headline-substitution — `sweep_audit`'s own failure mode, now self-applicable.
  Recorded as a `challenges` edge onto `artifact_sweep_audit`.
- **Honesty bound** (in the verdict + selftest): `flip_risk` assumes run-to-run
  independence — a floor on the gap; correlated failures widen it. The rig
  measures the gap for a supplied scenario; it does not estimate any real loop
  scenario's p.
