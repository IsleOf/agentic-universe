## What it shows
An LLM-based agent improves its **own** operating harness — no human engineers, no stronger external agent —
via an iterative three-stage loop:
1. **Weakness Mining** — model-specific failure patterns from *execution traces*
2. **Harness Proposal** — diverse yet *minimal* modifications tied to those failures
3. **Proposal Validation** — candidate edits accepted **only after regression testing**

Instantiated on Terminal-Bench-2.0 / SWE-bench Verified / AppWorld × 3 base models from different families
(MiniMax M2.5, Qwen3.5-35B-A3B, GLM-5). **Across all 9 model-benchmark combinations, every final harness
improves both held-in AND held-out pass rates, relative gains up to 132%.**

## Why it matters
This is **nearly the project's exact `self_improving_harness` architecture** (`docs/self_improving_harness_plan.md`
three loops): Weakness Mining = the Phase 2 experience bank's step-level store; Harness Proposal = the Phase 3
proposer's "minimal + falsifiable"; Proposal Validation = `improvement_loop` + `holdout_tasks` held-out
regression. A working system with that shape, 9/9 improving held-out — **independent evidence the plan is not
just plausible but instantiable.**

And the **held-out gains are the counterpoint to RHO's self-preference inflation**: `probe_rho_holdout.py` says
trajectory-only self-preference gets ~33% held-out survival; Self-Harness validates against regression tests
and gets real held-out gains. The held-out validation is what makes the difference — exactly the plan's rule.

Also: "effective harness design is inherently model-specific" — matches `concept_generative_process_diversity`.
