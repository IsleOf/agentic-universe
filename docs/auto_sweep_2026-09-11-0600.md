The claim: almost all self-evolution effort goes into the *proposer*; the weak point is the *acceptor*.
"Keep it if the score went up", applied hundreds of times against the same noisy held-out estimate, is
**uncontrolled adaptive multiple testing** — the agent p-hacks itself into churn and drift. On Qwen2.5
0.5B–3B agents self-evolving at the prompt level (GSM8K / SVAMP / ARC-Challenge):

- genuine improvement hidden in noise → greedy commits **30–42% false**, **10–33% harmful** edits
- *no* real gain available → greedy makes **13–21 spurious self-modifications per run** (72–100% false),
  degrades the most fragile agent by **4.9 points**
- **PACE** (Paired Anytime-valid Commit Evaluation): recast committing as a sequential hypothesis test — a
  paired testing-by-betting e-process, candidate vs incumbent on identical instances, commit only on
  decisive evidence, per-decision false-commit probability controlled even under optional stopping. Commits
  the real one and essentially nothing else; matches greedy accuracy at lower variance and ~18% lower eval
  cost; holds at baseline when there is no gain to be had.

Directly applicable: `verify_loop_edit` is a deterministic threshold on a point estimate ("grounded risk
strictly decreases"), fired ~once per run but against the same 17-task held-out set 200+ times — no
statistical-validity guarantee. The adoptable fix is a paired e-process: commit on an accumulated e-value,
not on a point improvement.
