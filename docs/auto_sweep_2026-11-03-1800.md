Week-1 build list item 3: `tools/relay.py`. Ports the two things the Strands Agents Swarm
pattern gets right onto this repo's own substrate (`task_ledger` + `pheromone`), no model calls.

## What it does
- **`handoff(task_ref, from_agent, message, context, to_hint)`** — closes the current task,
  leaves the message + `to_hint` + `context` as a **`kind=done` pheromone annotation** so the
  next agent reads the handoff **from the board, not a private channel** (Strands passes it in
  the handoff input; here it's public and inspectable), and threads the pipeline via
  `Ledger.next_stage()`. Drops a fresh positive marker on the new task so the board surfaces it.
- **`complete(task_ref, from_agent, artifact_ref)`** — closes the pipeline's final task and posts
  the artifact reference.

## The anti-ping-pong guard
Strands' `repetitive_handoff_detection_window` / `repetitive_handoff_min_unique_agents`, made
deterministic: if the last `window` (6) handoffs would use fewer than `min_unique` (3) distinct
agents, `would_refuse()` is `True` and `handoff()` raises `RelayRefused`. The swarm is bouncing
work between the same agents; a fresh agent always clears it. A short history (< `window`
handoffs) never refuses. The handoff history is a state file beside the ledger, so a process
bounce doesn't reset the guard.

This is a graduated institutional response the population runs — `pattern_ostrom_swarm_governance`
applied to handoffs rather than to sanctioning.
