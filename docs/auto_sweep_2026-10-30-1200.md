# Autonomous sweep — 2026-10-30 12:00 (run 374)

## Increment
Implemented the upgrade run 373 named instead of leaving it as documentation: **a whitelist
over patch shape, replacing the blacklist over key names.**

## The change
Run 371's refusal matched key *names* — `remove`, `delete`, `modify`, … — so **`rm_nodes`
walked straight through.** Run 373 folded the reason (arXiv:2608.03609: equivariance is the
condition under which verifying an LLM-plus-harness deployment is tractable) and noted that a
longer word list is the same defect with more words.

So: **invert the quantifier.** Enumerate the shape that is allowed —
`{proposal_metadata, add_nodes, add_edges}` — and refuse everything else **identically,
whatever it is called**. Annotations go inside `proposal_metadata`.

That is equivariant for free: the decision no longer reads the name at all. It is also
strictly stronger, catching off-contract keys nobody thought to blacklist.

`_DESTRUCTIVE` survives only to *label* which flavour of off-contract key appeared. It is no
longer load-bearing, and lengthening it now changes nothing.

## The check that proves it
```
[ok] EQUIVARIANT: `rm_nodes` is refused exactly as `remove_nodes` is
[ok] the run-371 name blacklist would have MISSED `rm_nodes` (upgrade is real)
```
The second check asserts the *old* behaviour would have failed — so this isn't a claim that
reads well, it's a demonstration that the change did something.

## The trap I walked into
The first version of the whitelist **broke the gate's own selftest immediately.**

`acceptance_gate.check()` is **polymorphic**: `proposal` is a graph patch on the fold path and
a loop-harness **policy edit** (`rule` / `identity` / `scope`) on the `improvement_loop` path.
Applying the graph-patch contract to both refused *every policy edit*.

A whitelist is only safe if you know what the object **is**. The contract is now scoped to
objects that *claim* to be graph patches (carry at least one allowed key). Residual gap stated
in the code: an object with none of the allowed keys isn't patch-shaped and isn't checked here
— nothing in the pipeline produces one, and `check_patch` wouldn't read it as a patch either,
but that is not a proof.

**Caught by running it, not by reading it.** That is the second time in three runs that
executing the change surfaced something the design didn't.

## Migration cost, named
A whitelist has no room for benign extras. Legitimate metadata now needs a designated home,
and there is one (`proposal_metadata`) — but a caller passing a stray top-level annotation is
refused where before it was merely reported. That is the intended trade, not an oversight.
