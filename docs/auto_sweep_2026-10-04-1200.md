## What it shows
A deployed ordering agent is decomposed into a fixed layer taxonomy — ontology, intent, routing, decomposition,
escalation, safety, memory, cross-cutting envelope/defense — each exercised by its own assertion slice in a
**deterministic, no-LLM "pure" mode**. The pure suite (238 cases / 23 slices, **2.39 s, ~10 ms/case**) runs in
CI on every change against a **locked per-slice baseline**. Validated by controlled regression injection across
7 non-safety layers.

**Key finding — "masking":** the aggregate pass-rate barely moves (**-1.7 to -5.9 pp** for six local
regressions) while the matching slice **craters (-25 to -91 pp)**. The faulty layer's slice is the single
worst-hit in 5/7, top-3 in 7/7 (mean rank 1.29 of 19); replicates on a structurally different second tenant.

## Why it matters
- **The empirical case for `concept_verification_completeness_gap`** — a single held-out number *provably*
  misses per-component regressions. This is why `holdout_verifier2` (two independent scorers) and per-component
  checks beat one aggregate held-out score (`probe_composed_design`'s "execution-alignment failure" is the same
  phenomenon).
- **Independent production validation of Phase 5** (`exec_guard`'s no-LLM pre-commit gate), the two-verifier
  design, and the `improvement_loop` regression fixture — all done in a real deployed agent.
- **A cleaner layer taxonomy** (ontology / intent / routing / decomposition / escalation / safety / memory /
  envelope) than the harness registry's five kinds (prompt / tool / context / hook / topology) — worth
  adopting for per-component gating.
