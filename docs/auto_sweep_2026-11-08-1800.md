## The finding
*"Model upgrades are routine; memory migrations are not. An agent can keep the same memory store
and still forget."* Four representations of the same history across a model swap:

| representation | what happens on upgrade |
|---|---|
| **KG-fixed** (fixed-schema graph) | accuracy changes by **+0.0004 ± 0.0020** — reliable |
| **NOTES** (model-compressed text) | **+9.91 or −13.28 pp**, asymmetric by migration *direction* |
| **RAG** (chunked, embeddings) | a 50/50 mixed index captures only **4.96** of the 11.90-pt re-embed gain |
| repair | store-only NOTES repair fails **all 48** cases; retaining raw history repairs **34/48** |

Decomposition: **80%** of the NOTES deficit is information lost at *initial construction*; **81%**
of the RAG deficit is *retrieval* failure. Recommendations: direction-specific migration
testing, strict embedding-space isolation, **retain source histories**.

## Why it lands on the substrate
- **`task_ledger.py` is the KG-fixed case** (id/goal/status/stage/deps) — upgrade-robust.
- **`pheromone.py` `evidence` text is the NOTES case** — model-coupled, not portable. The fact
  that annotations *decay on a clock* limits the blast radius (right instinct), but nothing
  durable should live only there.
- **`register_health()` (run 405) reads that model-coupled text** — a model upgrade could move
  its English-function-word fraction without the board actually drifting; it needs a re-baseline
  after a writer swap.
- **The design doc's week-3 vector column is the RAG case** — strict embedding-space isolation
  or a full re-embed, *never a mixed index*.
- **"Retain the raw source history for repair"** is what `fractal_flock`'s append-only artifact
  store and `task_ledger`'s `.audit` log already are — the finding says never compress them away.
