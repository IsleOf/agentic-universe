- **`concept_reliable_self_improvement_needs_an_exogenous_acceptance_signal`** (VERIFIED, partially-validated,
  conf 0.73). **SEAL** — Sealed Exogenous Acceptance Loop (arXiv:2607.24300). The *verifier–deployment gap*:
  when the agent controls both the optimised object and its verifier, self-scores stay near-perfect while
  real performance degrades. Fix: keep self-authored tests but gate every candidate against the incumbent
  through *a fixed harness-side audit the agent cannot author or inspect*, returning **only accept/reject**,
  incumbent retained on a clear regression. Beats unprotected baselines over six models × three seeds;
  failures stratify by capability. Corroborated by **Falsifiable Release Gates** (arXiv:2607.13070) —
  pre-declared machine-checkable acceptance suites + standing invariants preserved across six releases of an
  open runtime, suite 122→563 tests, gated self-improvement compounding a small model 20%→70% *while
  auto-rejecting a candidate that only inflated confidence*.

  This is the project's Phase 3 design, published a third and fourth time (after ASG-SI, run 119, and
  Self-Harness): `holdout_tasks.py` = SEAL's sealed audit; `verify_loop_edit` accept/reject with incumbent
  kept = SEAL's loop; the IDLE-STATE RULE + `what_would_make_this_wrong` severity invariants = Release
  Gates' standing invariants.

- **`concept_self_improvement_evaluation_is_noisy_and_task_order_dependent`** (VERIFIED, partially-validated,
  conf 0.70). **Fragility** (arXiv:2608.18066, Aug 2026 — the most current word). Multi-run + shuffled-order
  re-evaluation of two memory-based self-improving methods: (1) agent evaluation is inherently noisy on
  multi-step tasks and *the self-improving loop amplifies the noise*; (2) improvement is highly task-order
  dependent — default orderings impose a hidden curriculum. Underspecification is the hypothesised cause;
  rubrics + environment feedback partially close the gap. The counterweight to the cluster above: even a
  sealed exogenous signal is noisy, so step-2 re-runs should report across multiple runs, and the held-out
  set's frozen task *order* is itself an implicit-curriculum choice.
