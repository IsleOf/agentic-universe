## The instrument I added last run to catch a miscalibration was itself miscalibrated. Twice.

Run 385 found `cohort_threshold` was implicitly a function of pool size, and fixed it by
**adding an instrument** — `noise_margin_sigma`. That instrument shipped with two hidden
parameter dependences of exactly the kind it existed to expose.

**Defect 1 — the assumed corpus.** The margin is computed from `benign_signal_mean`, a
constructor constant defaulting to **0.05**. `executor_pool`'s workers emit **0.02**. So on a
20-worker all-benign round it reported `σ = −0.37, below_floor=True` while the actual cohort
score was **0.40** — under half the threshold. It cried wolf at k=20 when the real ceiling was
k=45. It was measuring an assumption and never said so.

**Defect 2 — the wrong line.** The margin measured against `self.cohort_threshold` while
`round_verdict()` gated on `effective_threshold()`. So with run 385's *own adaptive threshold*
enabled — the fix for the previous run's defect — the margin reported "below the noise floor" at
k=50 and k=100 while the real gate sat a full **3σ** clear.

## Three instances, two runs, one shape
Run 385 fixed a threshold with a hidden parameter dependence and, in the same file in the same
run, introduced an instrument with one. The fix for *that* introduced a third.

Every instance is the same: **a quantity computed from a constant the surrounding system had
already moved.** The reason it keeps recurring is structural — each fix adds a new derived
quantity, and a new derived quantity is a new place for an assumption to hide.

That's `wiring-recreates-the-bug` and `instance-not-the-class` arriving together, at shorter
range than either had been observed at before: not one run later in another component, but
inside the same file, inside the same fix.

## What could and could not be fixed
**Defect 2 is a real fix**: measure the line the decision actually uses. It also buys a
self-consistency property — with the adaptive threshold on, the margin returns `adaptive_z`
*exactly*, and a selftest pins that at k=100.

**Defect 1 cannot be fixed the obvious way**, and saying so is the point. This class *cannot*
estimate the benign floor from the signals it sees, because separating benign from attack signal
is the very thing it's trying to do. The median is contaminated **by design** under the
fragmentation threat model — k/2 attackers move it.

So the median is used **only to detect disagreement** with the assumption, never to replace it.
The verdict carries `assumed_benign_mean` beside `observed_median_signal`, and a margin whose
assumption the observations contradict is reported **UNVALIDATED** rather than as a number.

> An instrument that cannot measure its own precondition should say so, not substitute a worse
> estimate and stay quiet.

## At the pool level
`executor_pool` still **refuses** a round when the monitor aborts — not accepting on absent
evidence is the safe side, and that doesn't change. What changed is that it reports
`decision_basis`: `"evidence"` vs `"unreliable_monitor"`, plus a caveat naming k.

Rejecting for a reason and rejecting because the instrument is out of range are different
events. Conflating them is exactly how run 385's k≥20 false abort would have been read as a
caught attack.

Configured honestly (`benign_signal_mean=0.02`, `adaptive_threshold=True`) the pool is clean and
`decision_basis="evidence"` at every k tested through 100.
