## The finding
Standard run logs record *what* happened but cannot answer two accountability
questions:

1. **Evidence sufficiency** — is each reported claim **recomputable from the
   retained evidence**? If the number in the report can't be re-derived from the
   logged artifacts, the claim is INVALID (or INCONCLUSIVE if evidence is
   missing).
2. **Coverage** — do the retained records **cover the committed experiment set**?
   A frozen, pre-committed manifest says what will run; the verifier detects
   **omissions** — a promised experiment quietly skipped.

Mechanism: a claim-relative receipt binds typed transaction evidence to a signed
manifest; a selective verifier returns PASS / INVALID / INCONCLUSIVE per claim.
Results: 1,392 historical records replayed exactly; all 5 manual audit verdicts
reproduced; 11/11 semantic faults caught, 0 false positives; **0.021%** inference
overhead, **9.9 KB** per transaction.

## Why it lands here
The loop's own accountability has **both** gaps:
- **Sufficiency:** a sweep doc asserts findings (numbers, "selftest GREEN", graph
  deltas); `loop_session` records the run; nothing verifies each sweep claim is
  backed by a graph node / file / selftest line. G1's `n_uncited_claims` is the
  crude version; "recomputable from retained evidence" is the strong one.
- **Coverage:** a sweep's **"Next"** section *commits* to a follow-on; the next
  run often does something else; nothing checks whether committed increments were
  done or explicitly deferred. This is the exact shape of the **run-368
  acceptance-gate bug** (logged only accepts, so couldn't answer the one question
  it existed for) — a coverage failure in the loop's own audit trail.

**Adoptable without keys:** a `coverage_check` that reads run N−1's sweep "Next"
bullets and asks whether run N addressed one (or the sweep says why not); a
`sufficiency_check` that every headline claim in a sweep names a graph node id, a
file path, or a selftest job. The signed-manifest / crypto-receipt half needs an
operator key — owner-gated, same class as the substrate's capability tokens.
