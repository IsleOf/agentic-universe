`propose_loop_edit(metrics)` turns a below-threshold metric into a concrete loop-harness edit + falsifiable
prediction (e.g. verified_citation_fraction < 0.60 → add "at most ONE unverified citation per run" to the
`context/loop_policy` component; predict it rises over the next 10 runs).

## The honest verification split
Phase 3's verifier runs on a frozen held-out set. For the loop harness:
- **validation_pass_rate** — computably verifiable (replay the corpus, count post-edit invalid commits). Full
  loop can run.
- **verified_citation_fraction and any quality metric** — BLOCKED. Needs a frozen batch of research questions
  the loop can be re-executed on, twice, with and without the edit. That does not exist. The proposer produces a
  grounded proposal; a human promotes it; the *next 10 runs* are the deferred verification. Same shape as
  `pattern_grounded_acceptance_only` under a missing oracle — recorded as a `challenges` edge.

## Caveat on the replayed metrics
The `evolution_log` is one line per run and marks "VERIFIED" only in the recent disciplined entries, so
`verified_citation_fraction = 0.40` is a **floor**, not a measurement. Live recording (run 67) fixes this
prospectively: `s.cite(id, verified=True)` is unambiguous.
