## What changed

**Wired in `tools/loop_session.py`, not `tools/loop_conductor.py`.** This was the
smaller, cleaner change: `LoopSession` already brackets every run, it is *not*
`AU_SELF_DESIGN_ACK`-gated (the conductor and proposer/conductor DECISION logic
are), and a ledger write at the run boundary is bookkeeping, not a
proposer/conductor decision. No `exec_guard` override was needed.

- `LoopSession.__enter__` -> `OrchestrationLedger().claim(run_no, agent="conductor")`.
- `LoopSession.__exit__`, **only on a clean exit**, -> `.complete(run_no,
  commit_sha, node_delta, edge_delta)`, taking the deltas from the run's own
  `graph_delta`. `commit()` now stashes the sha on the session so `__exit__` can
  use it (falls back to `"pending"` when the `with` block closes before the git
  commit; a post-commit `.complete` refreshes it).
- New `ledger_path` kwarg (same discipline as `bank_base`) keeps selftests off
  the production ledger. Both ledger calls are wrapped so a ledger failure never
  fails a run.

**Stale-in-flight guard:** `OrchestrationLedger.check_startable(run_no,
max_stale_hours=48) -> (ok: bool, reason: str)`. Refuses when a *different, lower*
run is still `dispatched` and older than the threshold (a crashed prior run that
never completed). A recent in-flight run does **not** block - the assumption is
another session is legitimately mid-run. A fresh session / the cron calls this
before starting.
