## What it is
Generating ML-library code in **architecture-specific programming languages (ASPLs)** — hard even for
expert humans, and with **few code examples** because ASPLs are esoteric and evolving. The LLM must do
complex reasoning with limited data. Their adaptive self-improvement agentic system reports **up to 3.9×
over a single-LLM baseline** on a purpose-built benchmark, open and closed models alike.

## Why it matters
- Most self-improvement work in the graph — ReST-meets-ReAct (run 122), RHO
  (`pattern_trajectory_only_harness_optimization`), Self-Harness (run 109) — assumes **enough trajectories**
  to filter or run self-consistency over. **This project's own middle loop does not have that**: one
  increment per run, sparse history.
- This is evidence that **adaptive** self-improvement — where the improvement strategy adjusts to task
  difficulty and the data actually available (cf. MetaSkill-Evolve's Allocator) — survives the
  scarce-data regime the harness loop actually lives in. Recorded as `supports`
  `artifact_phase3_improvement_loop` and `concept_recursive_meta_skill_evolution`, and `challenges`
  `pattern_trajectory_only_harness_optimization` (RHO's sample-averaging selection needs a rollout supply).
- **Caveat carried in the node:** "ML-library code in a fixed ASPL" is a narrow, checkable domain with a
  strong outer verifier (compiles / matches reference perf). The harness-edit domain has a weaker grader —
  the gain does not transfer for free.
