## Increment
Week-1 build list item 2: `task_ledger.py` gains a **`stage`** field
(`research → draft → critique → final`, orthogonal to `status`), so `next_ready()` becomes the
Sequential-protocol driver the swarm substrate needs.

## The question this answers
"Drop the Hierarchy and Roles" (`emergent_self_organizing_roles`) found a **Sequential**
protocol — agents take turns with visibility into prior outputs — beats both central control and
full autonomy. What is the *minimal* mechanism that produces "take turns with visibility into
prior outputs" **without** a turn-taking loop or a coordinator holding the turn pointer?

**Answer: it's already two primitives the ledger has.**

- **"Visibility into prior outputs" is a dependency.** `_deps_done` already blocks a `draft` task
  until its `research` task is `done`. `next_stage(tid, goal)` adds the follow-on task with
  `deps=[tid]` at the next stage — the research output *is* the draft's input, enforced by the
  existing dep check.
- **"Take turns" is a sort key.** `next_ready()` now sorts by `(STAGE_RANK, created, id)`, so
  every ready `research` task is handed out before any `draft` task. The fleet moves through the
  pipeline in lockstep. Ties within a stage still break on age — fully deterministic.

No coordinator, no turn pointer, no message bus. The file decides, exactly as
`pattern_deterministic_task_ledger...` established for plain ordering.

## Details
- `add(goal, stage="research")` — default; unknown stage rejected at `add()`.
- `next_stage(tid, goal)` — the pipeline-threading helper; raises past `final` (a `final` task
  is *completed*, not advanced).
- `next_ready(by_stage=False)` — restores the pre-392 flat-queue behaviour.
- **Backward compatible:** a task dict with no `stage` key (a pre-392 ledger) defaults to
  `research` in `next_ready` and `list`.
- `list` and the CLI (`--stage`, `next --any-stage`) updated.
