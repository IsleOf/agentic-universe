# Autonomous sweep — 2026-11-12 18:00 (run 429)

## Increment
Fix, surfaced by run 428's own experience. `tools/loop_action_class.py` — the
action-class view of the loop's increments — had two miscalibrations that were
**inflating the apparent `fold` monoculture** by dragging non-fold runs into
`fold`.

## The two bugs

**1. The "cited + fold verb → fold" override matched the bare token "fold".**
The override (added run 426) exists to catch a run that *folds a paper and then
acts on it* — call it by the dominant verb, `fold`. But it tested
`re.search(r"\bfold", text)`, which matches the habitual status-line phrase
`acts foldNN%` that most increments carry. So run 428 (a `probe` that
operationalised run 427's fold) classified as `fold` **twice** before its prose
was reworded to avoid the word. Narrowed to `_FOLD_VERB` — an actual fold verb
adjacent to the citation: `folded` / `folding` / `fold(ed|ing) arxiv` /
`literature fold` / `fold the paper`.

**2. `_LEADS_CONSOLIDATE` did not recognise "a deliberate consolidate".**
It only matched `consolidation pass` / `consistency pass` etc., and scanned just
the first 40 characters. Run 421 — a deliberate world-model consolidation that
also fixed a stale claim it found — opened "Run 420's follow-on, a deliberate
consolidate" and was missed, then fell through to `fix` (it mentions "fixed"
later) or, under the old broad override, `fold` (it cites arXiv:2609.01861).
Widened the window to 60 chars and added `deliberate consolidat(e|ion)` and
`synthesis pass|run`.

artifact of the classifier, not the loop.
