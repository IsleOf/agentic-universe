## What changed
- **`sufficiency_check(run_n)`** — over a sweep's finding-bearing sections, every
  line asserting a checkable result (a percentage, a "GREEN", a "→", a "Γ =") is a
  **headline**. A headline is **backed** if it — or the doc — names an arXiv id, a
  `tools/*.py` path, a `selftest` reference, a `VALID`, or a graph node / edge /
  pattern id. Unbacked headlines are listed with a flag.
- **`coverage_check(run_n)`** — run N is **covered** if its increment (sweep +
  `run-N.json`) addresses at least one distinctive token from run N−1's sweep
  `## Next` bullets, **or** the increment explicitly explains a pivot (`fresh
  axis`, `switching`, `resting point`, `consolidation pass`, `continue
  literature`). A run that silently ignores every option its predecessor gave it,
  with no stated pivot, is a **COVERAGE GAP** — the run-368 acceptance-gate-bug
  shape (a record that can't answer the question it exists for).

Heuristic, in the open like `param_invariance_audit` / `loop_action_class`: it
reports a list and a flag, the judgement stays manual. The signed-manifest /
cryptographic-receipt half of ClaimReceipt needs an operator key — owner-gated,
same class as the substrate's capability tokens.

**A parser fix found during the build:** multi-line `## Next` bullets must be
joined with their indented continuation lines — the first cut read only a
bullet's first line and false-flagged run 440 (which *did* do the §8 catalogue its
predecessor named).

Run on the recent corpus: runs 435–441 all read clean (each addressed a prior
Next option or explained a pivot); no unbacked headlines.
