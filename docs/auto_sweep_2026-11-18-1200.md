## What changed
- **`refix_check(run_n, *, window=15)`** — for each **"fixed X"** claim in the
  window of sweeps before `run_n`, check that **X was re-measured**:
  - **same-sweep** — a re-verify word (`re-ran`, `re-measured`, `regression`,
    `still GREEN`, `confirmed`, …) near the claim, *or* the fix names code
    (`tools/x.py`, `module.attr`) and the sweep shows `selftest GREEN` / `VALID`;
  - **later** — a subject token plus a re-verify word in a *later* run's
    increment.
  A prose-subject filter (≥ 3 stopwords) drops meta-commentary that trips the
  `_FIX_CLAIM` regex.
- CLI `report` gains a **REFIX** line.

Two parser fixes surfaced during the build: `**Fixed:**` markdown bold broke the
separator character class, and the selftest fixture's run numbers collided with
real `run-N.json` records that `_increment_text` reads (moved to `>9000`).

## Result on the real corpus
Every named historical fix claim in reach (runs 400, 409) shows as **re-verified**
— the loop's run-`selftest_all`-on-every-commit discipline means named fixes to
code are re-exercised in the same commit. An honest confirmation, not a
free pass: the check would flag a doc-only fix or a fix claim with no verification
token anywhere.
