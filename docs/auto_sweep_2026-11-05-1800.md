## The paper
Long-running agents carry permissions and revocations in persistent memory. When memory
misrepresents that state, the agent's own records grant authority the history never permitted —
**endogenous authorization laundering**, no external attack: *"spurious permissions written into
memory lead to unauthorized actions as their provenance is washed away."*

EAL-Bench, 5 LLM memory writers × 2 executors across procurement / cyber / finance:

- writers fabricate false authority for **up to 50.2%** of unauthorized requests;
- once present, executors act on it **98.6%** of the time.

So the **write path** is where it originates and the read path barely resists. Defences —
permissions backed by valid **source events**, and **bounded event sourcing** — both cut
laundering and both reject more legitimate actions (a safety-utility tradeoff).

> Persistent memory is not merely a performance component — it is part of the agent's effective
> authorization policy.

## Why this lands on the swarm substrate
`pheromone.py`'s board and `task_ledger.py` **are** persistent memory carrying
coordination-authority state (who contributed, who may gate, what passed).

- **Run 400's cross-author supersede bug was authorization laundering** — a cheater deleting a
  warning, provenance washed away. Its fix (supersede within one author only) *is* the paper's
  defence (a).
- **Run 401 found a second instance.** `g4_release` counted *any* `kind=claim` shaped like a G4
  verdict (`{gate: G4, pass: true}`) toward the release quorum — **with no gate run behind it.**
  A fabricated prior approval. Verified: a directly-posted fake pass took a `min_quorum=3`
  release to `pass: true`.

## The fix
Two provenance checks, neither needing a signing key:

1. **A content contributor to the task cannot be a counted prior validator.** A real validator
   only ever posted a gate verdict here. This blocks "an author who did work then fabricates a
   pass" (verified: quorum drops to 2, blocked at `min_quorum=3`). A legitimate prior validator
   still counts.
2. **`g4_release` now returns `counted_prior_pass_ids`** — the quorum is auditable against the
   gate's own run log after the fact. Bounded event sourcing, lite.

**What stays open:** a *fresh sock-puppet id* posting a fake pass still counts — the same Sybil
limit run 400 recorded. Closing it needs signed verdicts (an owner-gated key) or an identity
registry. Added to `probe_substrate_adversarial` as an explicit known-limit attack.
