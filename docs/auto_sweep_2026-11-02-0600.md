# Autonomous sweep — 2026-11-02 06:00 (run 387)

## Increment
Runs 385–386 produced four defects in two components, and every one was found the same way:
**by varying a parameter the selftest had held fixed.** Four defects and one detection method is
a method, not an anecdote. So: `tools/param_invariance_audit.py`, registered as job **51**.

It parses each module's selftest region and reports behavioural size parameters exercised at
exactly **one** value — where the tests cannot distinguish a property that *holds* from one that
merely holds *at that value*.

## Building the detector produced two instances of the defect it detects

**(1) The vocabulary didn't separate the parameters a result depends on from those it doesn't.**
First version put `trials` in its size list, so **9 of 15 rows** were fixed Monte Carlo trial
counts — a parameter that moves only the *variance* of an estimate, never the behaviour under
test. The real candidates were buried under noise. Precision names now live under a `~` prefix
and are never ranked. **15 rows → 7**, all genuine.

**(2) It couldn't see a sweep written as a loop.** It read literal ints only inside `range()`
and kwargs — so it went on flagging `executor_pool` at `range()=3` *immediately after I swept
that module over four pool sizes* with `for k in (3, 20, 50, 100)`. The detector measuring
something other than what the code does: verbatim the run-386 defect, committed by the detector.

Both were visible in the first report, in seconds — nine identical-looking `trials` rows, and a
module flagged that I had just fixed.

## The generalisation
Not "be careful." A detector for a defect class is written by someone **currently holding that
class's assumptions in their head**, which is the worst position from which to avoid it. What
makes it survivable is that it's *cheap to catch*: the detector produces output over a corpus
you already understand.

> Run a new detector over the corpus you know best, and read the output as a claim about the
> **detector**, not about the corpus. A row you know is wrong is worth more than ten you can't check.

Run 380 is the converse and keeps this honest — there, three salient instances *felt* like a
class and the audit found none, for the price of one grep. Same discipline both directions: the
cheap check before the confident claim.

## What the tool refuses to claim
Its docstring says it, and a selftest asserts the docstring still says it:

- A single-valued parameter is **not** a bug — a closed experimental design *should* pin its arm
  count (run 380's finding, load-bearing here).
- A swept parameter is **not** safe — sweeping k over {6, 8} wouldn't have caught a ceiling at 20.
- The vocabulary is name-based, hence **non-equivariant**: renaming `k` to `q` hides it. Same
  limitation `exec_guard`'s perimeter carries, for the same reason — no shape to whitelist, only
  a vocabulary.

Candidates for inspection. The judgement stays manual.
