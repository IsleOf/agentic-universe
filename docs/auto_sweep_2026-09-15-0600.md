`tools/improvement_loop.py` gains **`paired_eprocess(paired_deltas, *, lam=0.5, alpha=0.05)`** — a
testing-by-betting e-process for the paired null *"the candidate is no better than the incumbent on
identical held-out instances"*:

```
e_n = ∏_i (1 + λ·X_i),  X_i = sign(candidate_i − incumbent_i) ∈ {−1, 0, +1}
committed  ⟺  e_n ≥ 1/α
```

Under H0 each factor has mean ≤ 1, so `e_n` is a non-negative supermartingale with `e_0 = 1`; by Ville's
inequality `P(sup_n e_n ≥ 1/α) ≤ α` **even under optional stopping** — so a commit carries a per-decision
false-commit probability of at most `α` however many times the loop peeks. Distribution-free (uses only
the sign of each paired delta — no score calibration).

Wired into `verify_loop_edit` as `evidence["paired_eprocess"]`, **advisory**: the held-out re-run is
single-shot (one delta per task, n ≤ 17), so this becomes load-bearing only once a re-run yields repeated
measurements (e.g. SEA-style best-of-k per task).
