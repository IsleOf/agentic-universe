## The one real gap it found
The agent-id normalisation runs 400 and 402 introduced — `_norm_agent` (strip + casefold, so
`alice` / `Alice` / `alice ` are one principal) — was applied to `gates.py` and `pheromone.py`
but **not** to:

- **`relay.py`'s anti-ping-pong window.** `_recent_agents` and `would_refuse` compared raw
  strings, so an agent bouncing work could keep the distinct-agent count above `min_unique`
  with whitespace/case variants of its own id.
- **`reputation.py`'s `_agent` keying.** `alice` and `Alice` accrued **separate reputation
  records and separate selection scores.**

Both modules are **explicitly listed in the run-402 trust-boundary node** as identity-keyed
guards that inherit the normalisation — so that node overstated coverage. Fixed both this run: a
shared `_norm` matching `pheromone._norm_agent`, plus a selftest check in each
(`relay`: whitespace/case handoff variants collapse to one distinct agent; `reputation`:
`Alice` + `alice ` → one record, one snapshot entry).
