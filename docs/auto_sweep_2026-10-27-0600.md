## What was broken
Before picking an increment I ran `janitor.classify` over the recent corpus. The kind mix
looked healthy — 5 `fold` / 5 `build` over 14 runs, no mode concentration. Then:

```
runs citing evidence roots: 0
```

**Signal 1 — `distinct_evidence_roots`** (input to `loop_metrics.run_novelty` and
`loop_conductor._corpus_drift`) is populated only by an explicit `LoopSession.cite()` call.
Runs 334–360 folded **eight arXiv papers and called `cite()` zero times**. Every status line
said `novelty n/a`; I saw it and didn't chase it.

**Signal 2 — `graph_delta`** (input to `idle_run_streak`) is set only by an explicit
`graph_write()` call, which the loop also never made — it edits the graph via standalone
scripts. Worse, `None` meant *both* "this run wrote no graph" and "this run forgot to
record it". Conflating those is what hid it.

Result: `idle_run_streak` had climbed to **27** — the plateau detector reporting `STOP` —
across runs that changed the graph every single time. Both inputs to the loop's only genuine
repetition check were dead, and a plateau check on *kinds alone* would have passed too.

## The fixes (`tools/loop_session.py`)
- **`_autocite_from_increment()`** — scans the increment line for arXiv ids on `__exit__`
  (while the recorder is still open, since `cite()` writes a CLAIM event) and records any not
  already cited.
- **`_autodelta_vs_head()`** — derives `graph_delta` as *working tree − last commit*, not
  from an in-session snapshot. The loop edits the graph **before** opening the session, so an
  `__enter__` snapshot would contain the run's own changes and always read zero.
  Delta-vs-last-commit is also the more meaningful quantity: what *this run* changed.

**The bound that keeps both honest:** derivation may populate a **count**, never a **quality
claim**. Auto-extracted citations are `verified=False` *always* — deriving "verified" from a
string match would inflate `verified_citation_fraction`, a metric the project uses to check
*itself*, i.e. grader-gaming against its own gate
(`concept_gate_faces_a_pretrained_grader_gamer`). Explicit `cite(verified=True)` and explicit
`graph_write()` both still win and are never doubled.

+8 selftest checks (14 total), including `auto-cite NEVER marks a citation verified` and
`an explicit graph_write survives the auto-derivation`.

## The generalisation
New node: **a self-observability metric the agent must remember to populate will read empty
exactly when the agent is busiest** — that is when attention is on the work. Derive it from
an artifact the work already produces. Derivation may populate a count, never a quality claim.

This sits *below* `concept_ahe_three_observability_pillars…` and
`concept_agentic_governance_needs_unified_observability…`: those name which observability you
need; this names the failure underneath them — the right field, present, and never filled.

## A discipline note for future folds
Auto-cite is a **safety net**, not a substitute. When a fold actually fetches and checks an
abstract, the run should call `cite(id, verified=True)` explicitly — otherwise
`verified_citation_fraction` will drift down as auto-cites accumulate, which would understate
real verification work just as surely as auto-verifying would overstate it.
