## What changed
`skill_induction.py` classified the loop's increments into a **flat** list of `TASK_CLASSES` —
the bottleneck Trace2Tower (run 418) names. Added:

- **`SKILL_LEVEL`** — maps each task class to one of three abstraction levels:
  - `idiom` — a reusable local move (a code pattern, a check, a fix shape)
  - `procedure` — a multi-step routine (`fold → probe → fix`; classify-before-generalise)
  - `strategy` — a run-selection principle (consolidate before a feature run; recency weighting;
    the IDLE-STATE RULE)
- **`level_of(cls)`** — the level, defaulting unmapped classes to `procedure` (a new kind of
  increment is more likely a multi-step routine than a one-move idiom or a standing strategy;
  mis-labelling toward the middle is the least harmful default).
- **`skill_key(note, outcome=...)`** → `"<level>/<class>@<outcome>"`; the caller stamps
  `outcome` from the run record (`ok` + `graph_delta` → `landed`; a later withdrawal →
  `withdrawn`; `held` only after the holdout set re-scored it).

This doesn't rebuild the spectral tower — it makes the *key* two-axis, so a future skill store
can group by level and filter by outcome, which is the shape Trace2Tower's ALFWorld 87% result
rests on.
