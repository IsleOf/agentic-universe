Week-1 build list item 5: `tools/gates.py`. G1 (evidence) and G4 (release) — the two gates that

## G1 — evidence
- **Hard fail:** no evidence links at all, or an evidence link naming a repo file that doesn't
  exist.
- **Reported, not blocked:** claim-shaped lines (a number, a `%`, an arXiv id, an assertion
  verb) with no nearby citation marker. The gate does *not* silently block on a regex —
  `concept_verification_completeness_gap` says computed checks miss design and convention, so the
  fuzzy call ("is this claim actually supported?") stays with a reader.

## G4 — release, quorum not veto
PASS requires **all** of:
- computable checks pass (caller-supplied bool);
- **zero** live `warning` annotations on the task;
- `(this validator) + (prior independent G4 PASS annotations) + (1 if computable_ok) ≥ min_quorum`.

A single validator can post a `warning` to **block** but cannot **pass** alone. A failing
computable check blocks release **even with five validator passes** — tests failing is a veto no
quorum overrides.

## Why a gate here can't calcify into authority (the owner's stated concern)
1. **Stateless.** Reads `task_ref` + annotations + artifact text, emits a verdict, forgets. No
   private model of the project for authority to accrete into.
2. **Single-use + rotated.** `_guard()` raises `GateRefused` if the validator contributed to the
   artifact, or ran the same gate on it last time.
3. **Verdicts are ordinary annotations.** A pass is `kind=claim`, a fail `kind=warning`, both via
   the same `pheromone.annotate` any agent uses. A later agent can contradict one and reopen the
   task.
4. **Quorum, not veto.** Reputation accrues to *agents* (`reputation.py`); a gate is a function
   agents temporarily compute.
