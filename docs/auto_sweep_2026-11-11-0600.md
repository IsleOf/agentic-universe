## The finding
LLMs formulate optimization models from natural-language descriptions, but real OR requests are
**incomplete** — missing objectives / constraints / rules change the resulting program — and
existing evals **assume a complete spec**, so they never test whether an agent knows *when to
clarify*.

**OR-Clarify:** partial public description + withheld structured **hidden slots** + bounded
interaction with a simulated user. Measures four things existing evals don't: **slot recovery,
stopping behaviour, silent assumptions, interaction cost.**

**InterOPT:** two-stage — identify unresolved **formulation-critical** gaps → decide
ask-next-question vs stop. Substantially beats baselines on exact slot recovery (choice-based).

**The reframe:** OR assistance is a **selective completeness decision** — clarify when needed,
stop when ready, **quantify what remains missing.**

## Why it lands here
- It's the **ASK action class** from `concept_aggregate_accuracy_masks_action_class_miscalibration`
  made concrete: *"silent assumptions"* is exactly the failure mode of an agent that TOOL_CALLed
  when it should have ASKed, and slot recovery / interaction cost are the diagnostic.
- Same shape as the gates' **"escalate on unparseability, don't pass"** (run 404) — a gate that
  can't read its input should ASK, not certify.
- **The swarm substrate has no ASK primitive.** An agent `contribute()`s on whatever's on the
  board. `pheromone.warn()` (run 399) is the nearest shape but flags suspicion, not a
  formulation gap. Design note: a `kind=ask` annotation (*"this task_ref is under-specified,
  clarify before drafting"*) and a G1 output line *"N unresolved formulation-critical gaps"*
  would give the substrate the selective-completeness decision this paper formalises.
