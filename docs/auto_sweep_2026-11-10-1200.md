## The finding
A common way to improve an LLM agent's scaffold: coding-agent-as-optimiser — read scores +
traces, iteratively edit the source. Each edit is chosen from a **belief about how the
environment will respond**, and that belief is **implicit** — in the coding agent's reasoning on
the current call, or latent in its parameters. Later calls see the scores and traces but not the
belief.

**BCO** writes the belief into a **persistent, continually-revised in-context document** — a
world model, "the current account of how the environment responds to edits."

- Higher train passrate than a matched control lacking *only* the world model, on 5 benchmarks.
- The gap holds on **every held-out split**.
- **Survives a target-model swap** (frozen model replaced, scaffold kept).
- Ablation: a fresh predictor given the accumulated document forecasts environment response
  *more accurately* than one given no document or a **same-form-but-falsified** copy — the
  document carries reusable information in its **content**, not just its form.

## Why it lands on this loop
The Agentic Universe loop **is** a scaffold-optimiser: each run reads the graph + `loop_metrics`
+ the sweep docs and makes an edit. Its belief about how increments move the metrics and the
frontier is **scattered across 400+ sweep docs and the graph edges** — never a single revisable
account of *"here is how a fold vs a probe vs a fix changes novelty / verified-fraction / the
open frontier."* `loop_metrics` computes the numbers; nothing holds the belief about *why* they
move.

It's the **third complementary written memory** the loop lacks as a single document:
- DiagEvo — what *fails*, by cause
- Trace2Tower's tower — what *works*, by abstraction level
- BCO's document — what the *environment does* in response to an edit
