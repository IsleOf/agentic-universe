## What it shows
Instruction hierarchy is a **model-side** defence (instructions get privilege by source). But the
**harness assembles the context for each model call**, and that assembly can **elevate low-level content
to a higher instruction level**.

- **Instruction privilege escalation:** an attacker induces the agent to elevate low-level malicious
  content; the elevated content then causes the agent to execute instructions it wouldn't follow at the
  original level. **13 attack objectives across 6 coding-agent harnesses** — confidentiality / integrity /
  availability / **RCE**.
- Two classes (companion paper): **MessageRole-CPE** (attacker content from a low-privileged context put
  into a higher-privileged message *role*) and **Cross-Scope-CPE**.

## Why it matters
- **The harness itself is a privilege-escalation vector** — context assembly is a trusted operation that
  can be subverted. A hard requirement for `pattern_execution_layer_enforcement` / Phase 5, and for
  `concept_agentic_os`'s runtime-as-fixed-point: **the assembler's privilege-labelling logic belongs in
  the runtime, not the mutable harness.**
- Harness tampering (run 189) by an **external attacker via the context channel**.
- `pattern_five_w_message_instrumentation` — the instruction **level** and its **original source** must be
  Five-W fields; content in a role above its source level is the MessageRole-CPE detection signal.
- Type-aware compaction that pins "rules" must verify the rule's **provenance, not its label**.
- **Related (small/local-model):** local models at Linux privesc succeed on only **8–16% vs frontier**
  (arXiv:2604.27143); six failure modes map to harness techniques.
