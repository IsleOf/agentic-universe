## What it does
`Conductor.conduct(run_no)` runs one loop increment as a deterministic pipeline:

1. **`pick_increment(recent_kinds)`** — the IDLE-STATE RULE (run 80) as a classifier:
   - selftest RED → the only allowed kind is `fix`
   - literature frontier open → `fold` / `build`
   - last 3 runs all doc/hygiene **and** frontier swept → `must_be_abc` — the increment
     must be `deepen` / `probe` / `consistency`
   - otherwise → any kind
2. a **`task_ledger`** task for the run
3. a **`Supervisor`** dispatches it to **`run_worker`** — the caller-supplied generative
   edge (this is where a real `call_model` will live)
4. the worker returns `{kind, patch, baseline_scores, candidate_scores, forecast, repaired}`
5. the conductor refuses a `kind` outside the plan; runs **`knowledge_graph.check_patch`**;
   runs **`acceptance_gate.check`** (held-out + PACE + process-adjusted + forecast Brier)
6. on accept → **`apply_patch`** + **`commit_push`** (caller hooks) → `RunRecord` + the
   certificate

## Why it matters
This is the v1 interactive loop — the thing this session has been running 300+ times by
hand — turned into a headless deterministic function with the acceptance gate wired in.
Every model-touching or side-effectful step is a callback, so the conductor is pure-stdlib
and fully selftestable with fakes (9 checks, incl. IDLE-STATE refusal, a broken patch
rejected before the gate, a held-out regression rejected by the gate).
