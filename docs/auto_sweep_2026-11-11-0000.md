## What the world model got wrong, and the real cause
§2 first said: *"`verified-fraction` drifts down because every fold adds a verified-via-abstract
citation and the loop rarely upgrades abstract-reads to full-reads."*

Investigating: **that's not the cause.** `_autocite_from_increment` (run 361) extracts every
`NNNN.NNNNN` in the increment line and records it `verified=False`. Since ~run 400 the loop's
increments routinely **cross-reference prior folds** (*"refines the run-401 finding
arXiv:2609.01836"*), so every run auto-added one or more unverified "citations" that were **not
this run's sources** — 6/14 verified over the last 15 runs, dropping the fraction 0.90 → 0.83.

## The fix
The auto-extractor exists for runs that fold a paper and forget to `cite()` it (runs 334–360). A
run that **did** call `cite()` explicitly is doing its bookkeeping; other ids in the prose are
cross-references. So `_autocite_from_increment` now **returns early if the run made any explicit
citation.**

**General rule** (added to the world model's hazard table): an auto-populator for a metric
should only fire when the human/agent path is *empty*, not stack on top of explicit bookkeeping
— otherwise it turns a signal about work done into noise about what was mentioned.

**Prediction:** `verified-fraction` stabilises near 0.85–0.90 and the ~0.0015/run drift stops.
