# Autonomous sweep — 2026-10-05 06:00 (run 302)

## Increment
Built the v2.2 stdlib brick: **`tools/research_brief.py`** — the typed object a literature
scout produces, with a mechanised dedup check. No model.

## Why
Runs 240–246, 253, 296, 298 were all the same shape: the owner pushes a research `.md`,
the loop reads it, checks by hand what is already covered, folds only the new parts. That
hand-check is the load-bearing discipline (the owner's "do not duplicate work" directive).
`research_brief.py` makes it a function.

## What it does
A brief = `{source, fetched, currency_note, verdict, already_in_graph, candidate_nodes,
candidate_edges}`.

- `validate_brief()` — `currency_note` is **required** (recency weighting is not optional);
  `already_in_graph` must be present (the dedup review, `[]` allowed); node ids must be
  `lower_snake_case` slugs; `verdict ∈ {fold, partial-fold, already-covered, not-substantive}`
  must match whether candidates are present.
- `to_graph_patch()` — emits the `{proposal_metadata, add_nodes, add_edges}` shape that
  `knowledge_graph.check_patch` validates; defaults `status` / `verification_state` /
  `derived_from`.
- `check_against_graph()` — the mechanised dedup: an id collision is a **hard stop**; a
  candidate label sharing ≥ 4 significant words with an existing node's label is a
  `near_label`; a `near_label` the brief did not list in `already_in_graph` sets
  `unreviewed_overlap` — i.e. the scout did not actually check.
