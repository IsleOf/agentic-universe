## What it shows
Standard self-improving agents rewrite their own **task skill** (what the agent does) but the **improvement
procedure** (how it improves) is authored once and held fixed — *non-recursive*.

MetaSkill-Evolve makes it recursive with **two timescales**: every branch carries a task skill `s` **and** a
branch-local **meta-skill** `m = (ψ, σ, α, π, ε)` whose five components parameterise the **Analyzer, Retriever,
Allocator, Proposer, Evolver** agents of the improvement pipeline. Task skills evolve on a **fast** loop; the
meta-skill evolves on a **slower** loop **under the same pipeline applied to itself** — no additional model or
objective, all five agents sharing one frozen backbone.

Beats no-skill / static-skill / single-level-evolution on OfficeQA / SealQA / ALFWorld by **+23.54 / +16.09 /
+1.92** held-out points — domain-dependent (the ALFWorld gain is small).

## Why it matters
`docs/self_improving_harness_plan.md` §3 has three loops (inner task / middle harness / outer knowledge). The
**middle loop's own procedure is currently fixed** — `loop_proposer.py` is a heuristic. MetaSkill-Evolve says
the middle loop's machinery should also be under improvement on a slower timescale, using the same
held-out-validated pipeline. Recorded as a `challenges` edge to `artifact_phase3_proposer_context`.

The **Analyzer / Retriever / Allocator / Proposer / Evolver** decomposition is a cleaner improvement-pipeline
than the project's `loop_metrics` → `loop_proposer` → `improvement_loop` split — worth adopting.
