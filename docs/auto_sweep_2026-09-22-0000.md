## Real bug caught by the integration
`manifest_hash` originally hashed `{version_counter, body_hash}` per component, so an edit-then-revert produced
a **different** manifest hash even though every component body was byte-identical. That would have made the
Phase 3 comparison "did this result come from harness state X" unreliable — a reverted harness would look like a
new one. Fixed: `manifest_hash` is now over component **body hashes only**. Attribution is about which bytes
produced a result, not the path the harness took to that state.

This is the kind of thing only an integration test finds — each module's own selftest passed throughout.
