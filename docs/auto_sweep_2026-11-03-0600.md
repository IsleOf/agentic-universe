## Increment
Run 390's summary reported `retention_evaluated: true` / `unevaluated_expansion: false` — for a

## The bug
Run 388 built `_harness_delta()` to flag harness expansion that wasn't evaluated against the
holdout set. Its `_certificates_grew()` established a baseline with:

```python
subprocess.run(["git", "show", f"HEAD:{self._CERT_LOG}"])
```

But `runtime/observations/certificates/gate_certificates.jsonl` is **gitignored** — only the
`README.md` beside it is tracked. So `git show HEAD:` fails on every machine, `returncode != 0`,
`was = 0`, and the function returns `now (183) > was (0)` → **`True`**.

The instrument reported *"this run's expansion was evaluated"* **whenever a non-empty local
certificate log existed** — which, after run 340, is always. Since run 388 it has never once
measured what it claimed to. Every `unevaluated_expansion: false` in six runs of summaries was
vacuous.

## Same defect, one run after the node naming it
This is exactly runs 385–386 (an instrument returning a confident answer where it should
decline) and run 388's *own* finding (the retention gate wired to the wrong event). Run 388 built
an instrument to catch unevaluated expansion and it was broken from birth — a git baseline that
never existed.

And the docstring said the opposite of what the code did: *"Returns False when the log is missing
or unreadable — the conservative direction"* while the code returned `True` precisely when the
git baseline was missing. Run 380's residue applies exactly: intentional and accidental behaviour
are indistinguishable by reading, and the run-388 selftest never caught it because it set
`_CERT_LOG` to a nonexistent path *after* `__init__` had already snapshotted the real one — it
tested a case the production path never reaches.

## The fix
An **in-session snapshot**. `__init__` records `_cert_lines_at_open = _count_cert_lines()`;
`_certificates_grew()` compares that to the current count; `None` (unreadable) is kept distinct
from `0` (empty log) and either side `None` returns `False`.

The in-session baseline is the *correct* one here because the acceptance gate, if it fires for a
run at all, fires **during** the session — unlike the graph, which the loop edits *before* the
session opens, where `_autodelta_vs_head` is right to use git. Same primitive, opposite baseline,
because the two artifacts are written at opposite times relative to the session.

## Consequence for the record
Every `unevaluated_expansion: false` since run 388 should be read as *unknown*. Runs that
actually expanded the harness with no holdout evaluation: **382–383, 387, 390** (and this one).
The owner-gated follow-up — routing new-tool additions through holdout scoring — is unchanged and
now the flag that motivates it actually works.
