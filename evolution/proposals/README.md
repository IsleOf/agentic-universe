# Change Proposals

> **Optional during the emergence-first phase** (`docs/emergence_first_posture.md`).
> Proposals are no longer a checkpoint — direct edits to the canonical graph are
> permitted. Write one when a change is large enough to want the reasoning
> recorded alongside it; skip it otherwise. `check-proposal` still works and is
> still useful for staging a big patch before applying it. The gating language
> below returns with the verification phase.

New ideas, sources, and runtime observations enter as proposals before they alter stable graph knowledge. Each proposal should identify its claim, evidence, affected node/edge IDs, status recommendation, confidence, implication, and blast-radius classification. Runtime evidence may propose changes but cannot silently promote itself to stable knowledge.
